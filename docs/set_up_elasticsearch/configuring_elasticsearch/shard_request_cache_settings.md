# 分片请求缓存设置

当针对一个或多个索引运行搜索请求时，每个涉及的分片在本地执行搜索，并将其本地结果返回给协调节点，协调节点将这些分片级结果合并为"全局"结果集。

分片级请求缓存模块在每个分片上缓存本地结果。这使频繁使用（且可能代价高昂）的搜索请求几乎可以立即返回结果。请求缓存非常适合日志记录用例，其中只有最新的索引被主动更新 — 旧索引的结果将直接从缓存中提供。你可以使用分片请求缓存设置来控制缓存的大小和过期时间。

要了解更多关于分片请求缓存的信息，参阅分片请求缓存。

## 缓存设置

| 设置 | 类型 | 描述 |
|------|------|------|
| `indices.requests.cache.size` | 静态 | 缓存的最大大小，以堆的百分比表示。默认为 1%。 |
| `indices.requests.cache.expire` | 静态 | 缓存结果的 TTL。索引刷新时会自动使陈旧结果失效，因此你不需要使用此设置。 |
