# 查询上下文与过滤上下文（Query and filter context）

## 相关性评分

默认情况下，Elasticsearch 按**相关性评分**对匹配结果排序。相关性评分衡量每个文档与查询的匹配程度：

- 相关性评分是一个**正浮点数**。
- 它在 Search API 的 `_score` 元数据字段中返回。
- `_score` 越高，文档越相关。
- 不同查询类型计算相关性评分的方式可能不同。
- 评分计算还取决于查询子句运行在查询上下文还是过滤上下文中。

查询上下文计算出的分数以**单精度浮点数**表示，有效位数只有 24 bit。如果评分计算超过该精度，会转换为浮点数并产生精度损失。

## 查询上下文与过滤上下文的区别

查询子句的行为取决于它运行的上下文：

| 对比项 | 查询上下文 Query context | 过滤上下文 Filter context |
|---|---|---|
| 核心问题 | “这个文档与该查询子句匹配得有多好？” | “这个文档是否匹配该查询子句？” |
| 回答方式 | 不仅判断是否匹配，还计算相关性评分 | 只回答 yes/no |
| 是否计算 `_score` | 是 | 否 |
| 性能 | 需要计算评分，开销更高 | 不计算评分，通常更快 |
| CPU 消耗 | 高于过滤器，尤其全文查询 | 相比全文查询消耗更少 CPU |
| 缓存 | — | Elasticsearch 会自动缓存常用过滤器 |
| 适用场景 | 条件应影响匹配文档排序时 | 只需要筛选、不影响评分时 |
| 触发位置 | 子句传入 `query` 参数时 | 子句传入 `filter` 参数时 |
| 示例位置 | Search API 的 `query` 参数 | `bool` 查询的 `filter`、`must_not`；`constant_score` 的 `filter`；`filter` aggregation |

### 查询上下文

在查询上下文中，查询子句会判断文档是否匹配，并计算相关性分数，写入 `_score` 元数据字段。当查询子句传入 `query` 参数时查询上下文生效，例如 Search API 中的 `query` 参数。

### 过滤上下文

过滤器回答的是二值问题：“这个文档是否匹配这个查询子句？”答案只有“是”或“否”。

过滤的好处：

1. **简单二值逻辑**：只判断是否匹配，不计算评分。
2. **性能更好**：由于不计算相关性评分，过滤器比查询执行更快。
3. **缓存**：Elasticsearch 会自动缓存常用过滤器，提高后续搜索性能。
4. **资源效率**：相比全文查询，过滤器消耗更少 CPU 资源。
5. **查询组合**：过滤器可以与带评分的查询组合，高效缩小结果集。

过滤器特别适用于查询结构化数据，以及在复杂搜索中实现“必须满足”的条件。

## 结构化数据与常见过滤场景

结构化数据是指高度组织化、按预定义格式排列的信息，在 Elasticsearch 中通常包括：

- 数值字段：整数、浮点数
- 日期和时间戳
- 布尔值
- keyword 字段：精确匹配字符串
- geo-point、geo-shape

与全文字段不同，结构化数据格式一致、可预测，适合精确过滤。常见过滤应用：

- 日期范围检查，例如 `timestamp` 字段是否在 2015 和 2016 之间
- 指定字段值检查，例如 `status` 是否等于 `"published"`、`author` 是否等于 `"John Doe"`

过滤上下文适用于：

- `bool` 查询中的 `filter` 或 `must_not` 参数
- `constant_score` 查询中的 `filter` 参数
- `filter` aggregation

## 示例

以下查询会匹配同时满足以下条件的文档：

- `title` 字段包含单词 `search`
- `content` 字段包含单词 `elasticsearch`
- `status` 字段包含精确值 `published`
- `publish_date` 字段包含从 2015-01-01 起的日期

```bash
GET /_search
{
  "query": {
    "bool": {
      "must": [
        {
          "match": {
            "title": "Search"
          }
        },
        {
          "match": {
            "content": "Elasticsearch"
          }
        }
      ],
      "filter": [
        {
          "term": {
            "status": "published"
          }
        },
        {
          "range": {
            "publish_date": {
              "gte": "2015-01-01"
            }
          }
        }
      ]
    }
  }
}
```

`query` 参数表示查询上下文：`bool` 和两个 `match` 子句处于查询上下文，用于计算文档匹配程度。

`filter` 参数表示过滤上下文：`term` 和 `range` 子句只过滤文档，不参与评分。

匹配结果默认按 `_score` 排序，`_score` 越高文档越相关。

## 使用原则

- 如果某个条件应该影响匹配文档的评分或排序，使用**查询上下文**。
- 如果某个条件只用于筛选、不需要影响评分，使用**过滤上下文**。
- 对结构化数据、精确匹配、日期范围、状态值等条件，优先考虑过滤上下文。
