# 发现与集群形成

发现和集群形成过程负责发现节点、选举主节点、组成集群，以及每次集群状态发生变化时发布集群状态。

以下过程和设置是发现和集群形成的一部分：

- **发现** — 发现是在主节点未知时（例如节点刚启动或上一个主节点发生故障时）节点相互查找的过程。
- **基于法定人数的决策** — Elasticsearch 如何使用基于法定人数的投票机制，即使某些节点不可用也能做出决策。
- **投票配置** — Elasticsearch 如何随着节点离开和加入集群自动更新投票配置。
- **引导集群** — 当 Elasticsearch 集群首次启动时需要进行引导。在开发模式下，未配置发现设置时，节点会自动执行此操作。由于这种自动引导本质上是不安全的，在生产模式下运行节点需要显式配置引导。
- **添加和移除主合格节点** — 建议在集群中保持少量固定数量的主合格节点，并通过仅添加和移除非主合格节点来扩缩集群。但在某些情况下，可能希望向集群添加或从中移除一些主合格节点。本节介绍添加或移除主合格节点的过程，包括同时移除超过一半的主合格节点时需要执行的额外步骤。
- **发布集群状态** — 集群状态发布是已选举的主节点更新集群中所有其他节点的集群状态的过程。
- **集群故障检测** — Elasticsearch 执行健康检查以检测和移除故障节点。
- **设置** — 有一些设置可以使用户影响发现、集群形成、主节点选举和故障检测过程。
